# SW 短视频微服务平台：简历项目说明

> 项目性质：经原作者许可，基于开源项目进行个人重构与扩展。简历主线是可靠视频发布、内容消费互动、视频场景轻量商业闭环和受控 AI 助手；不把已移除的通用商城、订单、直播、聊天和后台存量模块算作个人成果。

## 可直接放入简历的版本

**SW 智能短视频微服务平台｜Java 后端 / 个人重构项目**

`Java 21 · Spring Boot 3 · Spring Cloud Alibaba · MySQL · Redis · RabbitMQ · MinIO · Milvus · FFmpeg · Spring AI · Vue 3`

面向创作者和内容消费者构建“上传—异步处理—内容分发—互动运营—轻量变现”短视频闭环，并将原综合业务骨架收敛为聚焦视频主线的微服务平台。

- 设计“MinIO 预签名直传 → 本地事务 Outbox → RabbitMQ → FFmpeg 转码/抽帧 → 状态回写”异步发布链路，拆分视频、处理任务和消息投递三类状态，避免大文件经过应用服务并解决数据库与 MQ 双写空窗。
- 针对重复消费和处理回写失败，引入条件状态迁移、消费幂等、处理租约和 Outbox 扫描补偿；关注流采用 TTL 延迟重试、DLQ 与审计式恢复。真实 DG—SW 联调中，外部审批恢复后任务最终达到 `PUBLISHED / SUCCEEDED`，重复执行由 DG 幂等记录拦截。
- 实现公开/关注双 Feed、视频与创作者搜索、点赞、收藏、评论、关注关系和创作者运营数据；Feed 使用游标分页，播放量通过 `(video_id, viewer_id, viewed_date)` 唯一约束实现登录用户每日去重。
- 在 Video 域实现“视频挂商品—Redis Lua 秒杀—优惠券—订单履约/售后”闭环，以 MySQL 唯一约束兜底一人一单，并区分事务回滚与取消后的库存补偿；12 个隔离买家争抢 3 件库存时成功 3 单、拒绝 9 单，MySQL 与 Redis 库存一致且无超卖。
- 基于 Spring AI + Qwen 构建 SSE 创作助手，由 Gateway JWT 和 ToolContext 绑定创作者身份；采用 Redis 最近会话、MySQL 可管理长期偏好、Milvus 用户隔离向量索引的三层记忆，事实查询绕过偏好召回，向量失败回退 MySQL。
- 建立成功发布、无效媒体失败、租约恢复、关注流死信恢复和真实播放互动 E2E；固定本机串行场景下，2 秒视频从预签名请求到 `PUBLISHED` 的 5 次回归 P50/P95 为 3.50/3.51 秒。

## 指标口径

- P50/P95 基线为同一开发机、1 次预热、5 次串行测量，只用于回归，不代表生产吞吐、并发上限或 SLA。
- 12 买家/3 库存是本机固定小样本并发正确性验证，只能证明本场景未超卖，不能换算成生产 TPS 或容量。
- `PUBLISHED / SUCCEEDED / SUCCESS` 分别对应视频状态、处理任务状态和 Outbox 状态，不能混为一个结果。
- DG—SW 联调是一条受控本地集成证据；SW 私有接口目前仍缺服务 Token/mTLS，不能表述为生产级零信任。
- Spring AI 能力是权限受控的创作者助手，不是自主 Agent；Python Agent 能力由独立项目 DG/FlowPilot 展示。
- Milvus 的固定向量写入、用户隔离检索和删除已真实验证；本轮命令行环境没有 Qwen Key，真实 Qwen Embedding 请求不列入通过证据。

## 投递时的取舍

- Java 后端岗位：优先保留异步发布、异常恢复、视频商业并发三条；Feed 和 AI 记忆按岗位 JD 与版面选择。
- Python Agent 岗位：SW 放在 DG/FlowPilot 后面，保留异步链路、恢复机制和真实跨项目联调三条即可。
- 一页简历空间不足时，优先删除前端视觉、模块删除行数和普通 CRUD 描述，不删除 Outbox、租约恢复、库存不超卖边界和真实验证数据。
