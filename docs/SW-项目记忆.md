# SW 项目专属记忆

> 这份文档用于恢复并持续维护 SW 的项目上下文。它不是简历成稿，而是后续开发、复盘和面试准备的事实基线。

## 1. 项目来源与目标

- SW 基于开源原项目重构、扩展和升级，已获得原作者允许。
- 项目服务于中国大陆 2026 秋招准备，目标岗位以 Java 后端和 Python Agent 应用开发为主。
- 用户曾因电脑蓝屏重装系统丢失旧项目记忆和面试文档，因此本文件及同目录面试文档需要长期维护。
- SW 与 DG/FlowPilot 已分别完成秋招核心主线：SW 用于展示 Java 微服务与可靠异步链路，DG 用于展示 Python Agent 工程；两者保持独立，只通过受控恢复场景做集成验证。

## 2. 当前项目定位

SW 是一个面向创作者与内容消费者的短视频微服务平台。面试主线不是“模块很多”，而是：

```text
创作者上传
  -> 对象存储直传
  -> 业务状态、处理任务、Outbox 同事务落库
  -> RabbitMQ 异步转码和抽帧
  -> 处理结果回写
  -> 视频发布
  -> 关注 Feed 扇出、消费者刷流和互动
  -> AI 助手查询状态并诊断失败
```

当前判断：秋招核心项目已经完成并验证，已有代码、测试、脚本、可观测性、真实前端联调和 DG—SW 恢复演练支撑面试讲解。后续目标属于生产化增强，不应被表述为核心链路尚未完成。

## 3. 当前面试主线事实

### 已完成并适合作为主亮点

- Gateway：路由、JWT 鉴权、WebSocket 握手身份、私有路由阻断、Redis Lua 滑动窗口限流。
- User：注册登录、BCrypt 密码、JWT、用户资料、关注关系和粉丝分页查询。
- Video：预签名上传、分片上传、视频状态机、处理任务、Outbox、公开 Feed、关注 Feed、互动和评论。
- Video Processor：RabbitMQ 消费、FFmpeg 转码、封面抽帧、MinIO 读写、结果回写、租约恢复配合。
- 可靠性：Publisher Confirm/Return、Outbox 扫描补偿、状态条件更新、事件消费幂等、Feed Inbox 唯一约束、延迟重试、DLQ 和审计式恢复。
- AI：Spring AI + Qwen 兼容接口 + SSE；创作者身份由 Gateway/ToolContext 绑定，工具只读，支持处理状态查询和失败诊断。
- 可观测性：TraceId 贯穿 HTTP、Feign、Outbox 和 MQ 消息；Actuator、Micrometer、Prometheus、Grafana 和核心回归测试已接入。
- 本地证据：成功上传、无效媒体失败、处理回写不可用后的租约恢复、关注流死信恢复和互动验收均有脚本或测试支撑。

### 当前本机运行约定

- Java 服务统一由 IDEA 使用 JDK 21 启动，`dev` Profile 已写在各核心服务的 `application.yml`，不需要额外 Program arguments 或 VM options。
- Docker Compose 只运行 `sw-dev` 项目隔离的中间件；IDEA 进程通过 Windows 用户环境变量读取 MySQL、Redis、RabbitMQ、MinIO、Nacos 和 XXL-Job 凭据及 `SW_*` 宿主机端口。
- `.env` 只供 Docker Compose 读取，不能假设 IDEA 自动加载；修改 Windows 用户环境变量后必须完整退出并重启 IDEA。
- `QWEN_API_KEY` 不写入仓库或 `.env`，只在 AI Run Configuration 或 Windows 用户环境中本地注入。
- `SW-web` 未登录时只显示独立身份终端，登录后才显示 Feed、Creator 和 AI 具体页面；Feed 为竖向沉浸式播放器，支持私有 MinIO 预签名播放、公开/关注切换、游标加载、搜索、点赞、收藏和评论。AI 页面显式展示标题、简介/标签、选题、发布节奏和两类只读工具。视觉为原创 2077 式 HUD，不使用官方素材。
- MinIO 使用 `sw-dev` 独立数据卷和 `video`、`user` 两个私有 Bucket；启动脚本幂等初始化，不开放匿名读。上传使用预签名 PUT，播放使用短期预签名 GET。
- 2026-08-23 已重新完成真实闭环：视频 `2091483955474989057` 发布成功，Feed 返回签名媒体，Range 请求 206，浏览器播放器 `readyState=4`；真实 JWT 下点赞、收藏、评论与评论回读成功。
- 2026-08-23 已补齐短视频产品最小运营闭环：视频/创作者搜索与关注、我的收藏、资料修改、已发布作品删除、粉丝/关注数、作品互动汇总和 7 天观看趋势。播放以 `(video_id, viewer_id, viewed_date)` 唯一约束去重；接口返回本次是否新增计数，前端只在返回 `true` 时更新，避免重复播放的假增量。真实 E2E 已验证创作者发布后进入关注者 Feed、第一次播放 `true`、同日第二次 `false`、创作者观看数为 1 且趋势为 7 天。
- 2026-08-23 已完成 DG/FlowPilot 与 SW 的首次真实恢复闭环：隔离任务 `7321572775443310` 由 DG 真实调查，经过 LangGraph 提案、人工审批和受控执行调用 SW 私有恢复接口；SW 后验为 Video `PUBLISHED`、ProcessingTask `SUCCEEDED/retryCount=1`，恢复与发布 Outbox 均成功。该证据只代表一次受控本地集成 Demo，不代表生产 SLA 或服务间零信任认证。
- 跨服务评论聚合允许用户资料部分缺失：不存在的用户显示“已注销用户”；新用户空头像不会再进入 S3 签名流程。相关单测与现场联调均已通过。

### 2026-08-24 增强迭代（已完成本地闭环验证）

- 视频电商不恢复已删除的存量商城微服务，而是作为 Video 域内的轻量“内容带货”子域：创作者只能给自己的已发布视频挂商品，可配置每人限购 1 件的限时秒杀和优惠券；消费者可领券、下单、模拟支付、取消、确认收货和申请退款，创作者可查看订单、发货并审核售后。
- 秒杀入口使用 Redis Lua 原子校验活动时间、库存和用户资格，MySQL 订单唯一约束作为最终并发兜底。Redis 是抢购门闩而不是订单事实源；缓存丢失后由数据库已支付销量和待支付预占量重建剩余库存。
- 下单失败时释放 Redis 用户资格并回补库存；已落库订单取消/超时后保留“该用户已参加过活动”的唯一约束，只在数据库事务提交后回补库存，避免事务回滚却提前修改缓存。
- AI 个性化记忆按成本分层：Redis 仅保留最近会话，MySQL 保存用户主动确认、可查看和可软删除的长期偏好，Milvus 保存向量索引并按 `user_id` 隔离召回；不做自动抽取和重排，业务状态类问题绕过偏好记忆，向量服务失败时回退到 MySQL 最近偏好。
- 前端已加入视频商品卡、秒杀结算、我的订单/优惠券、创作者履约/售后和记忆增删入口。两份迁移已在 `sw-dev` MySQL 执行；Java 21 编译/打包、8 项新增定向单测、真实 Milvus 集成测试、商业/记忆 HTTP E2E、固定 12 买家争抢 3 件库存的并发场景和登录后浏览器验收均通过。
- 并发验证结果为 3 单成功、9 单售罄拒绝、MySQL 3 单、Redis 库存 0、无超卖，本机批次约 60.91 ms；该数据只用于固定小场景回归，不能当作生产 TPS、容量或 SLA。
- 当前命令行环境没有真实 `QWEN_API_KEY`，本轮只验证 Milvus 的固定向量写入/隔离检索/删除和 Embedding 失败后回退 MySQL，没有把真实 Qwen Embedding 请求写成已通过。历史 `VideoPrivateTest` 和 `InteractionTest` 已移除“读取数据库第一行/隐式调用 User Service”的环境耦合，改为确定性 Controller 委托单测；修正后 Video 全量 44/44、AI 常规套件均通过，真实 Milvus 测试另以开关运行 1/1 通过。

### 已主动移除的存量域

- 2026-08-23 已移除 `product`、`order`、`live`、`chat`、`admin` 五个孤立存量模块，以及对应的 Gateway 路由、4 份实际存在的 Nacos 本地配置和未使用 MinIO Bucket 初始化。删除前已核验主线模块 POM、Gateway、Compose 和 `SW-web` 没有依赖；历史可由 Git 远端恢复。
- `mcp-server` 保留为探索性工具适配模块，不属于 SW 当前完成能力，也不用于把 SW 包装成多 Agent 项目；真正的 Python Agent 项目是独立的 DG/FlowPilot。

## 4. 面试口径边界

- 不把本地固定环境串行 P50/P95 说成生产 TPS、并发上限或线上 SLA。
- 不把 Spring AI 创作助手说成自主规划、多 Agent、长期记忆或自动执行写操作系统。
- 不说 MQ 天然保证 exactly-once；准确说法是至少一次投递 + 业务幂等 + 状态条件更新。
- 不说所有事件都已 Outbox 化：视频处理、评论计数和发布扇出使用 Outbox；点赞/收藏当前通过状态缓存后发送 RabbitMQ 事件，消费端以 `eventId` 去重，后续可继续统一可靠投递。
- 不把当前观看统计说成生产数据分析：它只定义“登录用户对同一视频每日最多计一次”的演示口径，没有完播阈值、匿名去重、设备指纹、风控、离线数仓或反作弊能力。
- 私有接口被 Gateway 阻断主要是路由边界，不等同于完整的服务间零信任认证；这是可选增强目标。
- Video 的过期租约定时恢复默认开启；为本地人工或外部恢复编排联调，可仅在 Video Service 运行参数设置 `--sw.video-processing.automatic-recovery-enabled=false` 暂停定时扫描。该开关不影响私有 `recover-expired` 接口，演练结束必须移除，不能作为生产常态配置。
- “已验证”必须对应测试、脚本、日志、指标或现场演示证据，不凭代码数量推断完成度。

## 5. 推荐继续优化的目标

按优先级建议：

1. 将点赞/收藏事件统一纳入 Outbox，并为私有接口增加服务身份认证。
2. 使用 Testcontainers/Compose CI 与 Flyway/Liquibase 固化真实集成回归和迁移。
3. 为 FFmpeg 增加并发、超时、磁盘和进程资源隔离。
4. 为高粉丝创作者补充分批扇出、热点读扩散和 Inbox 治理。
5. 为 AI 工具增加结构化结果、注入防护、离线评测和模型降级。
